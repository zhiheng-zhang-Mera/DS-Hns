# Safe mechanism experiment protocol v1 — frozen before campaign outcomes

Date: 2026-10-26. Scope: A3 restart-budget component and A4 checkpoint-store component, with matched simple controls and external LangGraph SQLite checkpointing. No model/provider calls, desktop automation, service termination, host reboot or external side effects. This is a prospective exploratory mechanism study, not an ECQ evaluator campaign, full-product qualification, or cross-product reliability ranking.

## Inputs and interventions

Production modules are fixed at DS-Hns 6ae4dbc083efff0c4c611ca4e7a1f69823c2ccb6 (tree recorded by runner). The only product change since eeb57ca is the revision plan. Experimental adapters and protocol are committed before campaign measurement; fixture code is not production implementation. Full input/seed/config hashes and exact driver commit must accompany outcomes.

A3: 30 seeds for each burst, spaced, and boundary-window request schedule. Compare production createRestartBudget cap=3/window=1000 virtual ms, the same production module with cap lifted to 1000000, and an independently coded simple rolling-window limiter cap=3. All arms share zero cooldown/backoff, safeModeOnLoop=false and history maxEntries=1000 to isolate the budget cap. Bound schedules at 8 requests; no process is restarted. Independent oracle counts accepted attempts in [t-1000,t] and permits fewer than 3. Inputs, timestamps and per-request decisions retained. Primary outcomes: over-budget episode, oracle-decision disagreement; latency is microbenchmark-only. Repeating three schedule templates over seeds does not establish real-system reliability or independent fault families.

A4: seeds 1–30 for each no-fault, committed-boundary termination, and effect-before-checkpoint termination stratum. Each seed deterministically selects 8–16 append-only reversible steps, payloads, and an interior fault step. Four arms: production createCheckpointStore + verifyResume; checkpoint disabled/restart from beginning; independent atomic JSON completion cursor; external LangGraph with SqliteSaver and synchronous checkpointing. Same ordered step IDs/payloads, same effect-before-checkpoint order, same fault step and external terminal oracle. All writes stay within the episode scratch directory on D:. There is no transaction spanning effect and checkpoint in ANY arm. Therefore duplicate effects at the effect/checkpoint gap must be retained as counterevidence, not filtered or described as corruption.

All execution children are owned by the runner and can only be killed through their recorded ChildProcess handle. A child signals either committed progress or the gap after effect append; parent kills it only at that handshake, waits for exit, then starts a NEW child to resume. Boundary handshake must follow persistence. No-fault controls run to completion without injected death. Each process has 15s wall timeout; episode at most 35s, entire campaign hard timeout 30 minutes. Run serially, at most one child at a time. All arms receive same terminal oracle: every scheduled step occurs exactly once with correct payload and order; report completion separately from duplicate-free success and false success. Recovery time starts immediately before fresh spawn and ends at process completion, includes interpreter/import and startup, and is not a fair cross-runtime algorithmic speed comparison.

Arm order: alternate forward/reverse four-arm order by seed (ABCD/DCBA). A3 similarly forward/reverse three-arm order. No cold-start/warm-start claims. Episodes use fresh roots and databases; all four observations for a seed form ONE paired workload block. Fault strata remain separate. Seed schedule frozen in code and must not be changed after inspecting outcomes.

## Admission, failures and statistics

Campaign input schema checks run before experiments. Every attempt remains in append-only attempts.jsonl, including timeout, infrastructure error, protocol failure and process nonzero exit. No replacements in the confirmatory set; pilots are saved separately, marked PILOT, excluded prospectively. Product false-success/outcome errors remain admitted. The validator fails on corrupted metadata/aggregation, not intentional gap-fault outcomes. Output paths must be relative, references must resolve with digest verification; timestamps ISO UTC, candidate/tree/driver/config hashes consistent; duplicate episode IDs or seed/arm/scenario cells fail validation. A changed runner/protocol requires a new commit and campaign ID, never silent replacement.

Report per-stratum numerator/denominator, unique workload blocks, all errors and timeout counts. Wilson 95% intervals describe sampled fixture seeds only, not general production reliability. Bootstrap 95% paired mean differences/median latency differences by resampling the 30 seed blocks (10,000 resamples, fixed analysis seed), never step assertions or repeated endpoints. Report zero discordance against simple/external baseline as parity on this fixed fixture family, not equivalence proof. No p-value or powered confirmatory claim; primary safety behavior is structural and schedule-family dependent.

Stop on any unexpected write outside declared roots, inability to reap an owned process, unbounded process creation or protocol hash drift. Do not stop selectively on unfavorable scientific outcomes. At completion retain raw event streams, effect files, checkpoint snapshots/database, child stdout/stderr, all attempt metadata, independent oracle verdicts, generated summaries and checksum manifest. Large/local-only environments are excluded; exact requirements and source hashes retained. Full raw records must be published with paper-source links.

Other work: A1 authority-separation, A2 isolation, A5 full ECQ evidence binding, A6 Phase C, second host, real 24h task and physical reboot remain outside THIS protocol. Do not claim they are complete.
