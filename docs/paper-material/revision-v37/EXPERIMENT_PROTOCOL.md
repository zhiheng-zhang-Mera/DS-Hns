# ECQ v37 实验协议

协议草案：2026-10-27。执行者完成语义审查和开发集后，填写 `protocol/FREEZE.json` 并提交冻结版本，再运行评估集。

## A. 数据划分与主挑战集

六种结构模板：单 gate、多 gate、矩阵 gate、具有依赖的 gate、授权历史证据复用、嵌套声明。

| 集合 | 基础包 | 模板分配 | 每包案例 | 案例数 |
|---|---:|---|---:|---:|
| 开发 | 20 | 4/4/3/3/3/3 | 15 | 300 |
| 锁定评估 | 60 | 每模板 10 | 15 | 900 |

开发 seed 为 100–119；评估 seed 为 10000–10059。seed 和模板只是可重复生成索引。字段取值从 `SHA256(seed + NUL + fieldLabel)` 派生，记录确定性生成器版本。

每基础包生成：

1. 合法 PASS 控制；
2. 合法 FAIL 控制；
3. UNRESOLVED 控制；
4. 八个单目标变异，分别针对 S/R/G/V/E/C/I/T；
5. 四个组合变异：状态+运行、覆盖+范围、引用+完整性、声明+类型。

“单目标”指注入操作的目标，完整真值由实际关系决定。引用缺失可以同时产生 `I_E=VIOLATED` 与 `I_I=UNRESOLVED`。评估标签包含全部相关关系实例。

20 个开发基础包的所有派生案例均留在开发集；60 个评估基础包的所有变体均在评估集。生成后检查合同、规范化记录和工件内容的完全重复；重复时按固定派生 seed 重生成并记录替换，不删除预登记网格中的 case。同一模板的共享拓扑另行记录，不把拓扑相同等同于独立新结构；有效对照、授权跨运行复用、相同代码不同配置均须实际出现。

主比较四个方法共 3,600 条判定输出；独立抽样单位为 60 个基础包。八项义务各关闭一次的消融另存批次，评估同一 900 案例并记录能力变化。

## B. 标签与冻结

参考标签作者依据 RESEARCH_SPEC 及构造事实实现 `reference_labels.py`；判定器和标签器不共享检查谓词。共享 JSON schema、UTF-8 编码、通用哈希工具可以复用。

标签内容：`caseId`、`baseId`、`expectedClosure`、`expectedGateSatisfaction`、`expectedAuthorizePass`、完整关系状态和 witness。每个 witness 关联原始事实或合同条款。

人工或独立上下文审查覆盖六模板×十五变体的代表样本，重点检查合法 FAIL、授权复用、UNRESOLVED 和组合错误。开发审查完成后冻结规范、生成器、标签、四个判定器、数据划分、主指标和分析脚本的版本与哈希。

评估阶段给判定器的包中只含数据和合同。标签独立保存，执行结束后由分析程序读取。软件修订产生新的 `methodRevision/campaignId`；保留原输出并按修订批次报告。

## C. 跨来源 CI 重放

候选顺序固定：第一组 `pytest-dev/pytest`，第二组 `fastify/fastify`；备用依次 `pallets/flask`、`nodejs/undici`。先记录采集截止时间和资格规则，再按时间和 run ID 选取运行，采集列表在判定器读取结果前冻结。

资格规则：运行对应的源码提交、workflow、事件/矩阵上下文、job 结论和所需公开工件可定位；使用上述材料能独立构建研究所需合同。动态 requirement 无法还原的运行进入排除清单并注明缺失字段。

目标每外部项目 30 个不同来源运行：10 个开发、20 个评估。以源运行分组划分；同一运行所有变体留在同一集合。尽量纳入成功与失败的原始运行，并记录真实分布。实际来源数量、原始失败分布和排除原因全部进入采集清单。

对每个评估源运行生成原始记录与适用的预登记变体：错误代码版本、未授权跨运行拼接、删除必需 gate、改变声明范围/绑定、工件不可读取。目标为每运行 6 个 case；某变体不适用于该合同结构时记录 N/A，保持实际分母。40 个评估源运行最多 240 个重放案例。

原始记录反映真实 CI 输出；注入变体用于检验受控错误。两类分别汇总。原始失败不自动代表证据不闭合。

合同来自对应版本的 workflow、事件上下文和明确的资格声明，使用独立 expected-job 清单；适配器只改变表示。正常化验收对照源码状态、运行标识、必需/条件 gate、原始结论和工件映射，并保存 `mappingWitnesses`。

DS-Hns 的三个历史案例单独保存映射与关系诊断。历史 whole-run FAIL 仍保持 FAIL，历史案例不进入新控制挑战集分母。

## D. 判定与诊断指标

| 指标 | 定义 |
|---|---|
| 无效证据错误授权率 | 期望 closure 为 VIOLATED/UNRESOLVED 却获得 PASS 的案例数 / 该类案例数 |
| 合法 PASS 误拒绝率 | 完整有效、gate 满足而未获 PASS 的案例数 / 合法 PASS 案例数 |
| 授权判定正确率 | 正常完成且 authorizePass 匹配真值 / 全部登记案例；四方法共同报告 |
| 合法 FAIL 判定正确率 | closure=CLOSED、gate=UNSATISFIED、authorize=false 三轴均正确的比例；适用于提供完整三轴的方法 |
| 语义匹配率 | 三轴判定全部匹配独立真值的比例；适用于提供完整三轴的方法 |
| 关系级诊断 P/R/F1 | 对关系实例及 VIOLATED/UNRESOLVED 状态分别计算；保留每不变量结果 |
| 见证正确率 | 诊断所指对象和事实与金标准一致的比例 |
| 方法执行失败率 | 异常退出、运行错误、超时、功能未实现 / 登记方法调用数 |

总是同时报告错误授权与误拒绝，展示所有控制组。工具崩溃和超时单列为执行失败；在全案例授权正确率和适用的语义正确率中计为未正确完成。错误授权表同时列出各分母中的未完成数，避免零输出被理解为零风险的有效判定。B0/B1 没有实现的三轴或诊断指标填 N/A 并给能力覆盖，不将其包装成 UNRESOLVED 预测。

主效应采用按基础包分簇的配对 bootstrap：10,000 次、固定 seed 20261027，各变体随基础包一起重采样。跨来源重放按 source run 分簇并按项目分层。给出点估计、95% 区间、原始分子分母和来源分层。

每家族每基础包一个变体时可补精确配对检验。诊断依赖或样本结构变化要记录；按是否优于基线挑选显著性指标不属于本协议。

消融使用八次 leave-one-obligation-family-out。输出每个错误族的授权/诊断变化及不变量重叠表。评估是否遗漏范围、声明或类型关系产生具体错误，解释多个义务共同阻断的案例。

## E. 成本和第二环境

规模配置：10/100/1,000 个 gate，工件总量 1 MiB/64 MiB；共 6 个配置。每方法每配置预热 5 次，正式配对测量 30 次，方法顺序按固定随机方案轮换。

分别记录正常化耗时、常驻进程内规则检查耗时、含文件读取与摘要计算的端到端耗时、峰值内存。冷启动另表记录；记录缓存策略、计时单位、CPU/内存/OS、运行时和依赖锁。

使用两个可用 OS 环境（优先 Linux 与 Windows）重复主要判定与成本子集。若共享物理主机，环境表如实标注。第二环境重新运行冻结评估输入、重新计算主表，并比较排除计时和绝对路径后的规范化结果摘要。

已有 A3/A4 的 `recoveryMs` 是 launch-to-terminal-exit，继续按原勘误解释。v37 成本字段使用明确名称 `normalize_ms/rule_ms/end_to_end_ms/startup_ms/peak_rss_bytes`。

## F. 运行与材料清单

每批保存 `campaign.json`、`inputs.jsonl`、`attempts.jsonl`、逐例 `audit-result.json`、原始 stdout/stderr、错误日志、输入工件、独立标签、派生表格和 SHA256SUMS。

manifest 包含 source/method/normalizer/oracle/protocol/analysis 各自的提交和摘要。唯一键为 `(campaignId, caseId, methodId, methodRevision, attemptId)`。基础包、来源运行与派生案例的关联单独保存。

重试只增加 attempt；公开首轮结果、重试原因和最终使用规则。预登记输入应全部出现在结果账本中。实验完结后对预期案例键集合与实际集合做精确比较，再生成汇总。

实验代码和数据首先提交 DS-Hns 的 `scripts/ecq/`、`tests/ecq/`、`artifacts/paper-revision/ecq-v37/`。论文所需的可复算快照导出至 `Essay-Book/DS-Hns-H/arxiv/v37/artifact/`，最终 `submit/artifact-v37.zip` 可独立获取相应代码、输入和结果。
