# Threats to validity

- **Construct:** check counts are not interchangeable with reliability probability. Virtual hours are not wall-clock endurance.
- **Internal:** process startup, Windows scheduling, cache state, and test order affect Phase C timing. Only three repeats exist.
- **External:** one Windows 10.0.26200 x64 host and one Electron/DeepSeek Harness lineage were qualified. No Linux/macOS or multi-OEM evidence exists.
- **Ecological:** process acceptance watches a stand-in application; real Windows reboot and real 24h soak remain `NOT_RUN`.
- **Selection:** two published Cordis bundles plus one generated stranger do not represent the ecosystem.
- **Instrumentation:** CDP validates renderer behavior; OS-level wallpaper hit testing and foreground screenshots cover selected flows, not all input/accessibility paths.
- **Dependency drift:** external repositories are pinned for qualification, while future upstream changes require a new run.
- **Research:** no independent comparative baseline, participant study, field deployment, or literature-based novelty analysis exists.
- **Evidence:** immutable-run checks prevent mixing artifacts but cannot prove that a test measures the intended scientific construct.
