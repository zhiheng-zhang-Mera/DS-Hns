# Conditional qualification study protocol

Declared before evaluation-run analysis. The collection is frozen independently in collection-protocol.md; selection outcomes, unknown identities and API errors are not grounds for exclusion.

Development: 31 hand-specified authorization controls in controls/development.json, frozen df99f68481d7dd5caf4cbc125c2453b366e2f294e7bdf6aefd3014554a3b3a1d. They exercise known valid, known failed, absent, inactive, unknown, tolerated, dependency, matrix, duplicate, extra and identity/state cases. They are development controls, not held-out evidence. Exhaust all subsets of conclusion/runId/status erasures on the first two payloads per control, and all complete-payload subsets; retain fixed captureInventory. Count property violations separately from hand-gold authorization errors. Certificate attacks drop a slot/group or forge a name/source hash; independent source reconstruction must reject them. These finite checks test the proposition's implementation, not prove it for arbitrary workflows.

Comparators: same native qualification backend with (a) every job unconditionally required; (b) source groups and capture inventory rebuilt from surviving records; (c) unavailable guards treated as false. These are explicitly authored front-end ablations, not representative production tools or claims against general SHACL. Report false authorizations and false blocking on the fixed hand controls; never equate outcome-only workflow success to a qualified job execution claim.

Real archives: 80 development and 160 evaluation runs, transformations grouped by original run. Analyze exact head-source candidate snapshots and pinned reusable definitions. Historical root execution identity and full event payload are unavailable in all 240. Therefore report actual authorization under those unknown trust roots separately from source-snapshot conditional mapping/guard analysis. Never set identity verified merely to manufacture closed real-world contracts. Source-extraction agreement between independent implementations is not gold-label accuracy. Report all parse/unsupported/disagreement cases and complete/empty/incomplete API strata. Report project/workflow groups and cross-split revision overlap; no independent-commit holdout claim.

Cost: local Windows Node/Python; bounded controlled static matrices 1/10/100/256 slots, five warmups and thirty measured rounds per implementation/configuration, 180-second/configuration maximum. The initial design's1000-cell matrix was amended before formal benchmarking because GitHub's per-matrix bound is256; oversized input is a rejection control rather than a valid cost fixture. Measure YAML+contract compilation, qualification (which independently recompiles source), independent certificate check and total separately. Retain per-round values; censored cells are not assigned complete medians. Platform replay compares Windows/Linux correctness with pinned runtimes, not cross-machine speed claims.
